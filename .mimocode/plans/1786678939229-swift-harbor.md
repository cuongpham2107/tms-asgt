# Kế hoạch: Bỏ soft delete (xoá mềm) khỏi toàn bộ các bảng

## Tóm tắt (trả lời câu hỏi)

**Không phải sửa nhiều.** Thực tế chỉ có **2 model** thực sự dùng xoá mềm (`Customer`, `VehicleDocument`).
2 bảng còn lại (`vehicles`, `vehicle_maintenance_jobs`) có cột `deleted_at` nhưng model **chưa từng**
khai báo trait `SoftDeletes` → cột đó là "chết" (luôn NULL, không bao giờ được dùng).

`orders` đã xử lý xong ở lượt trước. Tổng cộng còn: **1 migration + ~8 file** + 1 test, không cần xoá dữ liệu
(kiểm tra: 0 bản ghi soft-deleted ở cả 4 bảng).

## Trạng thái hiện tại (đã khảo sát)

| Bảng | Model dùng `SoftDeletes`? | Ghi chú |
|---|---|---|
| `orders` | Đã gỡ ở lượt trước | ✅ xong |
| `customers` | ✅ Có (`Customer`) | cần gỡ |
| `vehicle_documents` | ✅ Có (`VehicleDocument`) | cần gỡ |
| `vehicles` | ❌ Không | cột `deleted_at` mồ côi |
| `vehicle_maintenance_jobs` | ❌ Không | cột `deleted_at` mồ côi |

Số bản ghi soft-deleted hiện tại: tất cả = **0** (không cần `forceDelete` dữ liệu).

## Các thay đổi

### 1. Migration (mới — 1 file)
`php artisan make:migration drop_soft_deletes_from_remaining_tables`
- `up()`: `Schema::table` cho 4 bảng, mỗi bảng `$table->dropSoftDeletes()`:
  `customers`, `vehicles`, `vehicle_documents`, `vehicle_maintenance_jobs`.
- `down()`: `$table->softDeletes()` cho 4 bảng trên.
- Không cần `DB::table(...)->delete()` (0 bản ghi soft-deleted).

### 2. Models — bỏ trait `SoftDeletes`
- `app/Models/Customer.php` — xoá `use SoftDeletes;` (dòng 13) + import (dòng 9).
- `app/Models/VehicleDocument.php` — xoá `use SoftDeletes;` (dòng 13) + import (dòng 9).

### 3. Filament tables — bỏ cột `deleted_at` + filter `TrashedFilter`
- `app/Filament/Resources/VehicleDocuments/Tables/VehicleDocumentsTable.php`
  - Xoá `TextColumn::make('deleted_at')` (dòng 66–70).
  - Xoá `TrashedFilter::make()` (dòng 73) + import `use Filament\Tables\Filters\TrashedFilter;` (dòng 8).
- `app/Filament/Resources/VehicleMaintenanceJobs/Tables/VehicleMaintenanceJobsTable.php`
  - Xoá `TextColumn::make('deleted_at')` (dòng 89–93).

### 4. Filament Edit pages — bỏ `ForceDeleteAction` + `RestoreAction`
- `app/Filament/Resources/VehicleDocuments/Pages/EditVehicleDocument.php`
  - Xoá `ForceDeleteAction::make()` + `RestoreAction::make()` (dòng 19–20) + 2 import (dòng 7–8).
  - Giữ lại `DeleteAction::make()`.
- `app/Filament/Resources/Orders/Pages/EditOrder.php`
  - Xoá `ForceDeleteAction::make()` + `RestoreAction::make()` (dòng 22–23) + 2 import (dòng 10–11).
  - (Trang này hiện đang bị comment trong `OrderResource::getPages`, nhưng vẫn giữ class nhất quán.)

### 5. Resource — bỏ override route-binding thừa
- `app/Filament/Resources/VehicleDocuments/VehicleDocumentResource.php`
  - Xoá method `getRecordRouteBindingEloquentQuery()` (dòng 68–74) — trùng lặp với `BaseResource`.
  - Xoá import `use Illuminate\Database\Eloquent\SoftDeletingScope;` (dòng 18).
- `app/Filament/BaseResource.php` (đề xuất, rủi ro thấp)
  - Xoá method `getRecordRouteBindingEloquentQuery()` + import `SoftDeletingScope` (dòng 7).
  - Sau khi bỏ toàn bộ soft delete, override này là no-op với mọi model → trả về hành vi mặc định của Filament.

### 6. Dọn import thừa (tuỳ chọn, cùng chủ đề soft delete)
- `app/Filament/BaseTable.php` — xoá `use Filament\Actions\ForceDeleteBulkAction;` + `RestoreBulkAction;` (dòng 8–9, chỉ còn trong comment).
- `app/Filament/Resources/Orders/Tables/OrdersTable.php` — xoá 2 import tương tự (dòng 35, 37).

### 7. Test
- `tests/Feature/OrderHardDeleteTest.php` (hoặc file mới `SoftDeleteRemovedTest.php`)
  - Thêm assertion `Schema::hasColumn(...)` = `false` cho 4 bảng `customers`, `vehicles`, `vehicle_documents`, `vehicle_maintenance_jobs`.
  - (Tuỳ chọn) thêm test hard-delete cho `Customer` / `VehicleDocument` tương tự test Order.

## Ngoài phạm vi (cố ý KHÔNG đụng)

- **Policies** (`app/Policies/*.php`): các method `restore`/`forceDelete`/`restoreAny`/`forceDeleteAny`
  do Filament Shield tự sinh cho **mọi** model (kể cả model không có soft delete như `Trip`, `TripCheckpoint`).
  Chúng độc lập với soft delete; chạy lại `shield:generate` sẽ sinh lại → giữ nguyên, không sửa.

## Xác minh (verification)

1. `php artisan migrate` — chạy migration mới (local SQLite, không mất dữ liệu).
2. Kiểm tra cột đã mất: `php artisan tinker --execute 'foreach([...4 bảng...]) ... Schema::getColumnListing(...)'`.
3. `php artisan test --compact --filter='OrderHardDeleteTest|SoftDeleteRemovedTest'` + chạy lại các test order/trip liên quan.
4. `vendor/bin/pint --format agent` trên các file đã sửa.

> Lưu ý: full suite hiện có ~15 test fail do `MissingAppKeyException` (`.env.testing` thiếu `APP_KEY`)
> ở các test render Filament/Livewire — lỗi môi trường có sẵn, không liên quan thay đổi này.
